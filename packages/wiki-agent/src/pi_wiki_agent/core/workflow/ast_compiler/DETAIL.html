1. 概述与设计目标

新编译器将 YAML 工作流定义转化为可执行的 Python 脚本，核心变化是用 Python ast 模块构建 AST 语法树替代原有的字符串拼接方式。

旧方案（字符串拼接）

lines.append(
    f"{var} = await agent("
    f"  {prompt},"
    f"  {{'label': {label}}})"
)
# → "_s1 = await agent(f'...', {'label': 'x'})"

引号/括号/缩进易出错，不可静态分析

新方案（AST 构建）

H.assign(var_name,
  H.await_expr(H.call_fn("agent", [
    prompt_expr,
    H.dict_literal({"label": label_expr})
  ]))
)

ast 模块保证语法正确，可做静态分析/优化

2. 整体架构与数据流

┌──────────────┐ YAML 文本 (.yaml) ───▶ │ ir.py │ ───▶ WorkflowDef (纯数据 IR) │ parse_workflow│ ├─ name, description │ _yaml() │ ├─ variables: [VariableDef] └──────────────┘ └─ phases: [PhaseDef] │ ┌──────────────┐ │ │ builder.py │ ◀────────────┘ │ WorkflowAST │ + resolver.py (变量→ast.expr) │ Builder │ + ast_helpers.py (AST 工厂) │ .build() │ └──────┬───────┘ │ ast.Module ┌──────▼───────┐ │ ast.unparse()│ └──────┬───────┘ │ Python 脚本字符串 ┌──────▼───────┐ │ run_workflow │ ← 沙箱 exec() │ (runtime) │ └──────────────┘

分层设计（每层独立、零耦合）：

  1. IR 层 — 纯数据结构，与 AST 无关
  2. 变量解析层 — ${...} 语法 → ast.expr 节点
  3. AST 构建层 — IR + 变量节点 → 完整 ast.Module
  4. 序列化层 — ast.unparse() → 字符串，喂给现有运行时
设计决策：输出仍是脚本字符串
run_workflow() 中的 parse_workflow_script() 负责 meta 提取 + 安全审计（_DeterminismVisitor），这是安全边界，不应绕过。AST 方案通过 ast.unparse() 生成字符串再传给现有沙箱，保持安全边界完整。

4. Schema 编译器

将 YAML 中的紧凑类型简写编译为标准 JSON Schema。

4.1 简写映射规则

YAML 简写JSON Schema
field: str{"type": "string"}
field: str?{"type": "string"}（键末尾 ? → 不加入 required）
field: int{"type": "integer"}
field: float{"type": "number"}
field: bool{"type": "boolean"}
field: [str]{"type": "array", "items": {"type": "string"}}
field: {enum: [a,b]}{"type": "string", "enum": ["a", "b"]}
field: {sub_a: str, sub_b?: int}{"type": "object", "properties": {...}, "required": ["sub_a"]}

4.2 递归编译实现

def compile_schema(shorthand: Any) -> dict | None:
    if shorthand is None: return None
    if isinstance(shorthand, str):       # str / str? / int / float / bool
        return {"type": _TYPE_MAP[base]}
    if isinstance(shorthand, list):      # [str] → array
        return {"type": "array", "items": compile_schema(shorthand[0])}
    if isinstance(shorthand, dict):
        if "enum" in shorthand:          # {enum: [...]}
            return {"type": "string", "enum": shorthand["enum"]}
        # nested object → walk key-value pairs, checking ? suffix
        return {"type": "object", "properties": ..., "required": ...}

5.6 ctx 上下文管理

Python AST 要求可赋值节点（Name、Subscript、Attribute、List、Tuple）携带 ctx 标识：

  • ast.Load() — 读取上下文（表达式）
  • ast.Store() — 写入上下文（赋值目标、循环变量）

name() 默认返回 Load；assign() 和 for_loop() 自动将目标设为 Store；_set_store_ctx() 递归处理 Tuple 等复合目标。

常见 bug：忘记设置 ctx 导致 TypeError: required field "ctx" missing from Name

6.4.1 文本分割器 (_split_vars)

def _build_join_fstring(template: str) -> list[ast.expr]:
    # template = "- ${item}"
    #
    # Step A: 用正则找到所有匹配
    matches = []
    # _JOIN_ITEM_FIELD_RE = r"\$\{item\.(\w+)\}"  匹配 ${item.xxx}
    # _JOIN_ITEM_RE       = r"\$\{item\}"         匹配 ${item}
    #
    # template = "- ${item}"  → matches = [(2, 9, None)]
    #                           (start=2, end=9, field=None 表示 ${item})
    #
    # 如果是 "- [${item.severity}] ${item.page}"  →
    #   matches = [(4, 20, "severity"), (21, 32, "page")]

匹配结果按起始位置排序，并排除重叠（${item} 是 ${item.xxx} 的子串，如果已被 field 匹配覆盖则跳过）。

    # Step B: 逐段交替构建 AST 片段
    pos = 0
    for start, end, field in matches:
        # [0, pos) 间的文本 → Constant 字面量
        if pos < start:
            parts.append(H.constant(template[pos:start]))
            # template[0:2] → Constant("- ")

        # [start, end) 间的变量 → FormattedValue
        if field is not None:
            # ${item.severity} → FormattedValue(Subscript(Name('f'), 'severity'))
            f_expr = H.subscript(H.name("f"), H.constant(field))
        else:
            # ${item} → FormattedValue(Name('f'))
            f_expr = H.name("f")
        parts.append(ast.FormattedValue(value=f_expr, conversion=-1))
        pos = end

    # 尾部剩余文本 → Constant
    if pos < len(template):
        parts.append(H.constant(template[pos:]))

    # 结果: [Constant("- "), FormattedValue(Name('f'))]
    return parts

7.3.3 checkpoint 断点续跑机制

流程分为两个分支：

条件行为场景
_p0_prev.get('value') is not None 直接从 _p0_prev['value'] 读取缓存结果，跳过 agent 调用 上次运行成功、重启后恢复
否则 执行 agent，完成后 checkpoint.save(...) 持久化结果 首次运行或上次未完成
Checkpoint 存储结构：
.wiki/checkpoints/<commit_hash>/Analyze.json
→ {"value": <agent 返回值>, "session_path": <JSONL session 文件路径>}

session_path 使下次运行可以通过 resume_from 从已有 session 继续对话，而非重新开始。

7.3.4 ${previous} 跨阶段/跨步骤链

第一阶段 Analyze 的 ${previous} 引用 _prev（初始为 None）。

第二阶段 Plan 的 ${previous} 引用 Analyze 最后一步的结果。链条如下：

Phase 0 (Analyze): _build_serial_steps(ctx.prev_var="_prev") _s1 = await agent("...${commit_message}...") ← ${previous}=_prev=None ctx.prev_var = "_s1" → 返回 (stmts, Name('_s1')) _s_result = _s1 _build_phase: self._chain_prev = "_s_result" Phase 1 (Plan): prev_var = self._chain_prev or "_prev" → "_s_result" _build_serial_steps(ctx.prev_var="_s_result") _s2 = await agent("...${previous}...") ← ${previous}=_s_result → 引用上一步 Analyze 的输出

在 _build_serial_steps 中，每一步完成后更新 ctx.prev_var，后续步骤的 ${previous} 自动指向刚完成那一步的结果。

7.4 Parallel 模式

7.4.1 无 for_each

_p1_results = await parallel([
    (lambda: agent(f'...', {'label': '...', 'agent': 'a1'})),
    (lambda: agent(f'...', {'label': '...', 'agent': 'a2'})),
])

7.4.2 含 for_each — 闭包捕获

_p1_items = <for_each 表达式>
if _p1_items:
    _p1_results = await parallel([
        (lambda it=_item: agent(...))
        for _item in _p1_items
    ])

关键点：lambda it=_item 利用默认参数在定义时捕获当前循环值，避免闭包延迟求值问题。

7.5 DAG 模式 — 最复杂

7.5.1 逻辑架构

加载 checkpoint → 获取 for_each 列表 │ ▼ for idx, it in enumerate(items): tid = it.get('id', f'task-{idx}') pe = prev_tasks.get(tid) or {} │ ├─ pe.value 非空 → 缓存分支（lambda 直接返回缓存值） ├─ pe 有 session_path → 恢复分支（agent 带 resume_from） └─ 否则 → 全新分支（正常 agent 调用） │ ▼ seed = {tid: v['value'] for tid, v in prev_tasks.items() if v.get('value') is not None} │ ▼ results_dict = await dag(dag_tasks, seed=seed) │ ▼ results = [results_dict.get(it.get('id', ...)) for idx, it in enumerate(items)] │ ▼ for idx, it in enumerate(items): # 保存 checkpoint _wr[tid] = {'value': r, 'session_path': cs if r is not None else old_s} checkpoint.save(...)

7.5.2 三分支详解

分支条件生成的 lambda用途
cached pe.get('value') is not None lambda v=pe['value']: v 直接返回缓存值，跳过执行
resume pe.get('session_path') lambda it2=it, sp=pe['session_path']: agent(..., resume_from=sp) 从已有 session 恢复继续
fresh 其他 lambda it2=it: agent(...) 全新执行

7.5.3 无 for_each 的 DAG

_p2_dag_tasks = [
    {'id': 'task-1', 'fn': lambda: agent(...), 'depends_on': []},
    {'id': 'task-2', 'fn': lambda: agent(...), 'depends_on': ['task-1']},
]
_p2_results_dict = await dag(_p2_dag_tasks)

7.5.4 seed dict comprehension

# 生成的 AST：
{ tid: v['value']
  for tid, v in _p2_prev_tasks.items()
  if v.get('value') is not None }

通过 dict_comp() 构建，Tuple 解包 (tid, v) 作为目标，is_not_none(get(v, 'value')) 作为过滤条件。

7.6 Pipeline 模式

_p3_items = <for_each 表达式>
if _p3_items:
    _p3_results = await pipeline(
        _p3_items,
        lambda _prev, _orig, _idx: agent(...),  # stage 1
        lambda _prev, _orig, _idx: agent(...),  # stage 2
    )

每阶段 lambda 接收 _prev（上一阶段输出）、_orig（原始 item）、_idx（索引），Stage 之间通过 _prev 链式传递。

7.7 Agent 调用构造

def _build_opts(self, step, label_expr, extra=None) -> ast.expr:
    """构造 agent() 的 opts 字典"""
    pairs = {
        "label": label_expr,
        "agent": constant(step.agent),
    }
    if step.output_schema:
        pairs["schema"] = constant(json.dumps(step.output_schema))
    if extra:
        pairs.update(extra)   # 例如 {"resume_from": sp_var}
    return H.dict_literal(pairs)

最终生成的 agent 调用 AST：

await agent(
    f'...prompt with {interpolations}...',
    {'label': '...', 'agent': 'agent-name', 'schema': '{"type":"object",...}'}
)

8. 完整编译管线

8.1 入口函数

def compile_workflow_yaml(yaml_text: str, agent_defs=None) -> str:
    """YAML → IR → AST → 脚本字符串"""
    wf = parse_workflow_yaml(yaml_text)          # ir.py
    builder = WorkflowASTBuilder(wf)              # builder.py
    mod = builder.build()                         # ast.Module
